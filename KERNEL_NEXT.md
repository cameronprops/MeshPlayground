# MeshPlayground kernel: next 10 steps

Goal: an offline, memory-conscious kernel for faithful inspection, repair and exchange of mesh, CAD and 2D data. Preserve input and report loss or uncertainty; do not silently mesh exact CAD or drop attributes. This is a plan, not a statement that formats below are implemented.

1. **Mesh groups and metadata.** Started: optional in-memory face groups and propagation through current proposals. Add optional, compact face-group membership, group identifiers and name metadata without duplicating geometry. Carry memberships through supported edits, and flag cases without a reliable mapping. Distinguish selection, group, object and connected component. First slice: in-memory mesh document and propagation for existing proposals.
2. **Representation and precision contracts.** Started: cross-format mapping, explicit length units, validated coordinate frames, scene resources, hierarchy and instancing, and basic 2D line/cubic paths. See [FORMAT_MAPPING.md](FORMAT_MAPPING.md) for shared concepts and format-specific conversion limits. Define document/object/instance hierarchy, units, coordinate frames and separate mesh, analytic/parametric CAD and 2D curve representations. Record source fidelity, tolerances, provenance and unsupported data. Do not promise exact conversion between fundamentally different formats.
3. **Attribute and topology identity.** Design consistent face, vertex, corner and edge attributes, plus stable IDs or explicit edit remaps for normals, UV seams, materials, groups, colors and tags. Define undo, stale proposals and snapshots without relying on unsafe indexing assumptions.
4. **Reliable format adapters and round trips.** Started: strict geometry-only OBJ read/write preserving polygon corners; other common OBJ records deliberately rejected until supported. Implement and independently test imports/exports incrementally: STL; OBJ with UVs/materials/normals; 3MF assemblies, transforms, units and properties; DXF/SVG 2D geometry and curves; FBX scene hierarchy, transforms, instances and mesh attributes; STEP exact geometry, topology, units and assembly structure. Track which variants and entities are preserved, converted or unsupported; not every file/version/extension can be assumed supported. Test separate applications and malformed inputs.
5. **Memory and scale.** Benchmark peak memory, time and geometry fidelity on increasingly large scans and real fixtures; use compact adjacency, spatial indices, incremental iteration and shared immutable data. Make budgets and cancellation explicit and preserve a safe reference.
6. **Topology and geometry triage.** Diagnose boundaries, non-manifold vertices/edges, duplicate/degenerate/overlapping faces, winding, disconnected and nested shells, and self-intersections including adjacency cases. Add independent truth fixtures and report uncertain numeric cases.
7. **Accurate local repair.** Build editable patch proposals for nonplanar and concave boundaries; support local subdivision and boundary constraints. Preserve unaffected surface, track replacement provenance, honor explicit limits, test sharp detail and curvature, and never claim to recover missing detail with certainty.
8. **Intersection resolution and parts.** Add robust intersection curves, local splitting, user-chosen union or separation and checks for nested shells. Validate geometry before and after; keep all changes reviewable and reversible.
9. **Deviation and CAD conversion.** Implement scalable bidirectional surface comparison with meaningful bounds and unit-aware tolerance policies. Add optional faceted and fitted CAD output, with complexity/deviation reporting, explicit unsupported cases and independent round-trip validation. Exact CAD B-rep and smooth surface fitting are not supplied by the current triangle mesh core.
10. **Solid preparation and release gates.** Add orientation, cavity classification, shelling and thickness/intersection checks; validate watertightness and intended openings. Provide headless and interactive adapters over the same kernel, and repeatable regression, performance and format corpus tests before labeling any result printable.

Priority note: the listed formats span fundamentally different domains. “Handle everything” is a target for coverage, not a promise that all optional extensions, encodings and proprietary features can be losslessly supported. FBX and 3MF include scene/attribute semantics; STEP includes exact CAD; DXF/SVG can contain 2D curves and non-geometry. Specialized readers, tested external libraries, or dedicated modules may be needed, with licenses and offline availability reviewed.
